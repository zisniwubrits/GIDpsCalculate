### 副词条

| 词条 | 权重 |
|---|---|
| 固定生命 / 固定攻击 / 固定防御 | 150 |
| 暴击率 / 暴击伤害 | 75 |
| 生命% / 攻击% / 防御% / 充能 / 精通 | 100 |

- 4 件套的**效果数值不建模**（用户在圣遗物域里自己固定）。

## 2. 代码约定

- **键一律 ASCII**：槽位 `flower / plume / sands / goblet / circlet`；
  副词条键与面板宏同名（`crit_rate / crit_dmg / atk_pct / atk_flat / hp_pct / em / er / …`）。
  中文只放显示标签（`SLOT_LABELS` / `SUBSTAT_LABELS`），**不得当字典键**。
- **数值单一来源**：平均值从 `nodes.RELIC_ROWS` 取（`_relic_average`），不要在 relic.py 里抄一份数字。
- **不用 `random`**：所有概率/期望都必须来自解析公式或**精确枚举**；需要抽样时必须单独开函数并显式传入种子。
- **"最好"必须按标量排序**：状态向量之间是偏序，互不支配时没有"最好"。默认标量 = 追踪属性的词条总数
  （`state_scalar`），将来可换成真实伤害（接上伤害链之后）。
- 追踪哪些属性由 `DEFAULT_TRACKED` 决定（默认 5 个伤害相关属性）；
  生命/防御/充能等不进状态时，**只占词条池**（通过"入选概率"体现，不能直接丢掉）。
- 所有函数是**纯函数**：不读写全局状态、不改入参、不打印。

## 3. 数学约定

- 单件状态分布 `P₁[i]`：`{(词条次数向量): 概率}`，概率和必须为 1。
- 累积 `S[s] = P(单件分数 ≤ s)`。
- **N 件最好的万能通式**：

  ```
  P_N[s] = S[s]^N − (S[s] − P₁[s])^N
  ```

  只能对**标量**分数使用；多维偏序直接套会算出和不为 1 的结果（历史坑）。
- 精度写法：`S^N − (S−P)^N = S^N·(1 − (1 − P/S)^N)`，否则两个接近 1 的数相减会丢精度。
- 期望的线性可以用，但**不能把 `E[f(X)]` 换成 `f(E[X])`**（Jensen）：
  伤害链非线性（暴击封顶、乘区相乘），两者必须分开标注。

## 4. 测试约定（`tests/test_relic.py`）

必须覆盖的"对拍"：

1. **概率和 = 1**（单件分布、N 件分布）；
2. **枚举期望 = 解析期望**（逐属性，1e-9）——这是最强的正确性检查；
3. **N=2 与暴力枚举取 max 对拍**（1e-12）；
4. 概率表合计 100%、权重合计 1100、满级值；
5. 单调性：N 越大期望最好分数不减；q4 越大（34% vs 20%）期望更好；
6. 点数随 q4 变化：8 / 8.2 / 9。

跑法：`python -m pytest -q`（在仓库根），提交前必须全绿。

## 8. 伤害函数抽象与 DLL 加速（计划）

目标：圣遗物模拟/DP 要调用伤害链**几十万到几百万次**，Python 的图求值太慢。
做法：把"某工程的伤害链"抽象成一个**纯数值函数**，编译成 DLL，用 `ctypes` 调用。

### 8.1 分层

| 层 | 内容 |
|---|---|
| 抽象层 | `DamageFn = Callable[[Sequence[float]], float]` + 固定的**属性顺序** `stats_order` |
| 解释层 | 现有 `Graph.evaluate` 包一层（等价但慢，作为回退与对拍基准） |
| 生成层 | 把工程链**常量折叠**后生成 C 源码（只含算术表达式，不执行用户字符串） |
| 编译层 | MinGW `gcc -O3 -shared` → `damage_<指纹>.dll`，缓存到 **`build/dll/`**（`build/` 已在 `.gitignore` 里） |
| 调用层 | `ctypes` 载入；**批量接口**一次算 N 组，减少调用开销 |
| 回退 | 没有 gcc / 编译失败 / 指纹不符 → 自动走解释层，结果必须一致 |

### 8.2 约定

- 导出 ABI（草案）：
  - `int calc(const double* x)` → 返回伤害（`x` 按 `stats_order` 排列）
  - `void calc_batch(const double* x, int rows, double* out)` → 一次算 `rows` 组
- **生成 C 代码必须白名单**：只允许数字、四则运算、括号、已知变量名；
  用户填的算式先用现有求值器解析成数字/四则表达式再翻译，**绝不把原始字符串拼进 C**。
- 等价性：同一批随机属性，DLL 与解释层的相对误差 < 1e-9（pytest 用例守住）。
- 指纹：工程 JSON + 属性顺序 + gcc 版本 → 变了就重新编译。
- **DLL 不进 git**（编译产物、与平台/编译器绑定）：输出目录固定 `build/dll/`；
  生成的 C 源码（`build/dll/*.c`）同样不进 git，需要留档时另存。
- 不使用 `private/` 存放构建产物（`private/` 是个人存档，语义不同）。
- 只在 `relic` 的模拟/DP 用 DLL；**不改变工程本身的求值路径**（前端 `/api/evaluate` 仍走 Python）。

## 9. 伤害函数的输入向量（仅副词条口径）

只考虑**副词条**能给出的属性时，会进伤害公式的恰好是 **9 项**（顺序固定，下标即约定）：

| # | 宏 | 中文 | 单位 |
|---|---|---|---|
| 0 | `atk_pct` | 攻击% | 百分数 |
| 1 | `atk_flat` | 小攻击 | 绝对值 |
| 2 | `hp_pct` | 生命% | 百分数 |
| 3 | `hp_flat` | 小生命 | 绝对值 |
| 4 | `def_pct` | 防御% | 百分数 |
| 5 | `def_flat` | 小防御 | 绝对值 |
| 6 | `em` | 元素精通 | 绝对值 |
| 7 | `crit_rate` | 暴击率 | 百分数 |
| 8 | `crit_dmg` | 暴击伤害 | 百分数 |

约定：

- **`er`（元素充能效率）不在里面**：它不进伤害公式，只在词条池里占权重（拉低有用词条的入选概率）；
- 主词条另算（`dmg` 元素/物理伤害、`crit_rate/crit_dmg` 冠、`atk_pct/em` 沙杯），
  需要时在模拟层单独叠加，不要混进这 9 项；
- 数值一律 `float`，百分数按面板口径（`25.0` = 25%）；
- 这 9 项是**圣遗物模拟**的输入；完整工程求值（含 `month_dmg / res_shred / …` 等 20 个宏）
  仍由 `Graph.evaluate` 负责，两者不混用。

### 9.1 已实现的接口（解释层）

`genshin_dmg/relic.py`：

```python
STATS_ORDER                      # 9 个属性名，顺序即 ABI 下标

fn = damage_fn_from_project(project, role)   # project = 工程 dict 或文件路径
fn.calc([...9 个 float...]) -> float          # 单次
fn.calc_batch(rows) -> list[float]            # rows = 行优先扁平数组（长度 = 组数 × 9）
```

- 内部用 `Graph.extra_own`（**新增**，在 `graph.py`）把属性注入成该角色的**自身值**：
  面板里写过的宏相加、没写过的也登记；因此 `own::` 会包含圣遗物，`in::` 不会；
- 输入校验：长度必须 9、不得 NaN/inf、批量必须整除，错误一律 `ValueError`；
- 同一个 `Graph` 实例可反复求值（`evaluate` 会重置运行时状态），所以批量只重建 `extra_own`。
